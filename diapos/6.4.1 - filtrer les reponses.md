# Filtrer / Mapper les réponses renvoyées par le service

----

## Filtrage statique

- l'annotation **@JsonIgnore** permet de cacher les attributs que nous ne souhaitons pas exposer en écrivant l'annotation sur l'attribut ou sur la classe en précisant les attributs à exclure
- l'équivalent en XML est **@XmlTransient** à écrire sur le getter

```java
// alternative sur la classe : @JsonIgnoreProperties(value = {"id", "prix"})
public class Vin {
    private Integer id;
    private String chateau;
    private String appellation;
    @JsonIgnore
    private Double prix;

    @XmlTransient
    public Double getPrix() {
        return prix;
    }
}
```

## Mapping via un DTO

Un DTO est un objet simple dont le seul rôle est de transporter des données entre l'API et le client, sans aucune logique métier. On distingue :

- le DTO entrant (création / mise à jour)
- DTO sortant (réponse de l'API) pour découpler le modèle de données de l'interface publique

Pourquoi ne pas exposer directement les entités JPA ?

- **Sécurité** : empêche un client malveillant d'injecter des données sensibles (forcer un id, modifier un statut admin...)
- **Découplage du contrat d'API** : le schéma de la base de données peut évoluer (renommage de colonnes, restructuration) sans casser les applications clientes qui consomment l'API
- **Fiabilité de la sérialisation** : élimine les boucles infinies de sérialisation Jackson sur les relations bidirectionnelles et évite les erreurs LazyInitializationException

----

## Mise en place d'un DTO avec les records

En Java moderne, un DTO s'écrit sous forme de record : immutable, concis et nativement sérialisable par Jackson sans code verbeux

```java
// DTO entrant : on n'accepte pas d'id à la création
public record VinRequest(
    String chateau,
    String appellation,
    BigDecimal prix
) {}
```

----

## Nommage des DTO

Le nommage des DTO repose sur une règle majeure : **expliciter le sens du flux (entrant ou sortant) et l'intention métier**, en évitant le piège du suffixe fourre-tout Dto.

Entrants :

- création : **CreateVinRequest**
- mise à jour : **UpdateVinRequest**

Sortants :

- vue complète : **VinResponse** ou **VinDetailResponse**
- vue allégée : **VinDetailResponse** ou **VinItemResponse**

----

## Le lien entre Entités et DTO

```java
@Component
public class VinMapper {

    public Vin toEntity(CreateVinRequest request) {
        Vin vin = new Vin();
        vin.setChateau(request.chateau());
        vin.setAppellation(request.appellation());
        vin.setPrix(request.prix());
        return vin;
    }

    public VinResponse toResponse(Vin entity) {
        return new VinResponse(
            entity.getId(),
            entity.getChateau(),
            entity.getAppellation(),
            entity.getPrix()
        );
    }
}
```

Alternative : mapping automatique avec **MapStruct**

----

## Utilisation du mapper dans le service

```java
@Service
@RequiredArgsConstructor
public class VinService {

    private final VinRepository vinRepository;
    private final VinMapper vinMapper;

    public VinResponse create(CreateVinRequest request) {
        Vin entity = vinMapper.toEntity(request);
        Vin saved = vinRepository.save(entity);
        return vinMapper.toResponse(saved);
    }
}
```
