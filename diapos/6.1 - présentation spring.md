# Présentation de l'univers Spring

----

## L'univers Spring

C'est un framework libre pour concevoir des applications Java. Spring s'occupe de l'exécution globale de l'application. Les développeurs peuvent se concentrer sur la configuration du projet et les traitements métiers.

- **Spring Core** : coeur de Spring qui gère la création et le cycle de vie des objets avec les annotations **@Autowired**, **@Controller**, **@Service**, **@Repository**, etc...
- **Spring MVC** : permet de construire des applications web basé sur l'API Servlet
- **Spring Data** : permet de gérer le mapping objet-relationnel (ORM)
- **Spring Batch** : permet de gérer les traitements par lots
- **Spring Security** : fournit des fonctionnalités d'authentification, d'autorisation et de sécurité
- **Spring Boot** : permet de créer facilement et rapidement des applications Spring avec un Tomcat embarqué

----

## Cycle de vie et versionnage de Spring Boot

Format : `MAJOR . MINOR . PATCH` (Semantic Versioning)

- Version Majeure (`X.0.0`) — Ruptures et nouveau socle
  - **Contenu :** *breaking changes*, refonte d'architecture, suppression des éléments dépréciés
  - **Socle technique :** Changement des prérequis minimaux (ex. SB2 : Java 8,SB3 : passage à `jakarta.*`)
  - **Cadence :** Espacée (tous les 3 à 4 ans)
- Version Mineure (`x.Y.0`) — Nouvelles fonctionnalités
  - **Contenu :** Ajout de fonctionnalités, nouvelles auto-configurations, annonces de dépréciations. Rétrocompatible
  - **Cadence :** **Tous les 6 mois** (calendrier fixe : mai et novembre).
  - **Règle de support gratuit :** **12 mois** par branche mineure
    > *Conséquence :* On a 6 mois pour réaliser une montée de version mineure en production pour continuer à recevoir les patchs de sécurité
- Version Patch / Maintenance (`x.y.Z`) — Stabilité et sécurité
  - **Contenu :** Corrections de bugs, correctifs de sécurité (CVE) et mise à jour des dépendances du BOM
  - **Garantie :** Aucune nouvelle fonctionnalité, impact nul sur le code existant
  - **Cadence :** Mensuelle (ou en urgence sur faille critique *zero-day*)

## Spring Boot : les principes

- **les starters**
  - un starter est un ensemble de dépendances prêt à l'emploi, par exemple pour le starter web, il y a *Spring MVC*, *Jackson*, *Tomcat*...
  - plus besoin de gérer les versions de chaque starter, uniquement la version du starter parent qui va gérer la version de toutes les autres dépendances
- **l'auto-configuration**
  - permet de configurer automatiquement l'application à partir des jars trouvés dans le classpath (nos dépendances)
  - plus besoin des fichiers *appconfig-mvc.xml*, *web.xml* et *persitence.xml* (Hibernate)

----

## Les principaux Starter

Starters "métiers"

- **Spring Web :** création de l'API REST (Spring MVC, Jackson, serveur Tomcat embarqué)
- **Spring Data JPA :** couche d'accès aux données (Hibernate, Spring Data, pool HikariCP)

Outillage développeur

- **Lombok :** élimine le code verbeux (génération automatique des getters, setters, constructeurs à la compilation)
- **Spring Boot DevTools :** confort de dev (redémarrage rapide lors des modifications de code, désactivation automatique en production)

Gestion des bases de données

- **H2 Database** : base embarquée en mémoire, démarrage immédiat sans installer de serveur SQL pour travailler en local
- **PostgreSQL** : base relationnelle d'entreprise via le driver `postgresql` pour travailler en hors prod et en prod

## H2 vs PostgreSQL : le rôle de l'ORM

### Pourquoi l'alternance fonctionne ? (la force d'Hibernate)

- **Abstraction du SQL :** Spring Data génère du code abstrait (JPQL / requêtes dérivées)
- **Le rôle du dialecte :** Hibernate détecte le driver (H2 ou PostgreSQL) et traduit le JPQL en syntaxe SQL adaptée au moteur sous-jacent :
  - Gestion automatique des limites de pagination (`LIMIT / OFFSET`)
  - Fonctions de date et concaténation adaptées au SGBD
  - Stratégies de génération des clés primaires (`IDENTITY` vs `SEQUENCE`)

----

## H2 vs PostgreSQL : ce qu'Hibernate de compense pas

### Où s'arrête la magie ?

- **Requêtes natives (`nativeQuery = true`)**
  - Tolérées si le SQL est strictement standard
  - Piège immédiat dès qu'on utilise des types ou fonctions propriétaires

### Les solutions d'atténuation

- **L'émulation (`MODE=PostgreSQL`) :** ajuste l'URL JDBC H2 pour tolérer la syntaxe Postgres, mais reste une béquille partielle
- **L'alternative moderne (Testcontainers) :** instancie un conteneur Docker PostgreSQL éphémère lors des tests, garantissant une parité stricte avec la production sans aucun compromis
