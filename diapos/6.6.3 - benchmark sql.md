# Benchmark & Stratégies d'extraction de données

----

## 1. Matrice comparative des approches

Comportement constaté sur 100k à 500k lignes :

| Approche | RAM | Débit | Code | Usage cible |
| :--- | :---: | :---: | :---: | :--- |
| **JPA Entités (`List`)** | $O(N)$ | 📉 Chute (GC) | ⭐ | CRUD unitaire (< 1k) |
| **JPA DTOs (`List`)** | $O(N)$ | 📉 Baisse | ⭐⭐ | Lecture seule (< 20k) |
| **JPA DTO Stream** | $O(1)$ | 📈 Stable | ⭐⭐ | Flux + Spring Data |
| **JDBC Stream (`JdbcClient`)** | $O(1)$ | 🚀 Max | ⭐⭐ | Export brut CSV/JSON |

> **Principe :** L'accumulation en mémoire (`List`) s'effondre avec le volume sous la pression du GC. Le streaming garantit un débit et une RAM constants en $O(1)$.

----

## 2. Les 3 pièges critiques du Streaming (PostgreSQL / JPA)

1. **L'illusion du streaming sans `@Transactional` :**
   - Par défaut (`autoCommit = true`), PostgreSQL **ignore le `fetchSize`** et charge tout en RAM JVM.
   - `@Transactional(readOnly = true)` est obligatoire pour activer le curseur côté base.
2. **Dimensionner le `fetchSize` (sweet spot : 1 000 à 2 000) :**
   - Compromis optimal latence/débit (blocs de 200 à 300 Ko).
   - Au-delà de 5 000, le gain de temps est marginal (< 3 %), mais mobilise inutilement la mémoire.
3. **Saturation silencieuse du cache L1 Hibernate :**
   - Hibernate conserve chaque entité en session $\rightarrow$ risque d'`OutOfMemoryError`.
   - **Remède :** Streamer directement un Record/DTO (`SELECT new ...`) pour désactiver le suivi d'état.

## 3. Implémentation : JPA DTO Stream

Association d'un Stream de Record et du `SequenceWriter` Jackson :

```java
@Transactional(readOnly = true)
public void streamJpa(OutputStream os) throws IOException {
    try (SequenceWriter writer = objectMapper.writerFor(VinResponse.class).writeValuesAsArray(os);
         Stream<VinResponse> stream = repository.streamDtos()) {

        Iterator<VinResponse> iterator = stream.iterator();
        while (iterator.hasNext()) {
            writer.write(iterator.next()); // Sérialisation unitaire vers la socket HTTP
        }
        writer.flush();
    }
}
```

- **Avantage :** Maintient l'abstraction Spring Data tout en garantissant une empreinte mémoire en $O(1)$.

## 3 bis. Implémentation : JDBC Stream (JdbcClient)

Contournement complet de l'ORM via le moteur d'exécution directe :

```java
@Transactional(readOnly = true)
public void streamJdbc(OutputStream os) throws IOException {
    try (SequenceWriter writer = objectMapper.writerFor(VinResponse.class).writeValuesAsArray(os);
         Stream<VinResponse> stream = jdbcClient.sql("SELECT id, chateau, prix FROM formation.vin")
                 .query(VinResponse.class)
                 .stream()) {

        Iterator<VinResponse> iterator = stream.iterator();
        while (iterator.hasNext()) {
            writer.write(iterator.next());
        }
        writer.flush();
    }
}
```

- **Avantage :** Débit maximal, aucun cycle de vie d'entités, mapping automatique vers le Record.

## 4. Synthèse des bonnes pratiques d'extraction

```txt
Quel est l'objectif ?
 │
 ├── 1. Affichage écran / Navigation IHM
 │       ├── Petit volume (< 1 000) ──► ✅ JPA classique (List<T>)
 │       └── Grand volume            ──► ⚠️ Bannir OFFSET / LIMIT
 │                                       ✅ Pagination par curseur (keyset) :
 │                                          WHERE id > :dernierId LIMIT 50
 │
 └── 2. Export de données (CSV / JSON)
         ├── Volume modéré (< 20 000) ──► ✅ JPA Projection DTO synchrone
         ├── Gros volume (Spring Data)──► ✅ JPA DTO Stream + SequenceWriter
         └── Débit maximal brut       ──► ✅ JDBC Stream (JdbcClient)
```
