# Benchmark & Stratégies d'extraction de données

---

## 1. Matrice comparative des approches

Comportement observé lors de l'extraction de gros volumes (100k à 500k lignes) :

| Approche technique | Empreinte RAM | Débit & Comportement | Complexité | Cas d'usage type |
| :--- | :--- | :--- | :---: | :--- |
| **1. JPA Entités (`List`)** | ⚠️ **$O(N)$** (Critique) | 📉 S'effondre (pauses GC) | ⭐ | CRUD unitaire, pagination (< 1 000) |
| **2. JPA DTOs (`List`)** | ⚠️ **$O(N)$** (Forte) | 📉 Décroît avec le volume | ⭐⭐ | Lecture seule synchrone (< 20 000) |
| **3. JPA Stream (`SequenceWriter`)** | ✅ **$O(1)$** (Minime) | 📈 Constant et stable | ⭐⭐⭐⭐ | Gros volume + calculs Java |
| **4. JDBC Stream (`JdbcClient`)** | ✅ **$O(1)$** (Minime) | 🚀 Débit maximal stable | ⭐⭐ | Exports massifs bruts (CSV / JSON) |

> **Principe clé :** L'accumulation en mémoire (`List`) perd en efficacité à mesure que le volume augmente à cause de la pression sur le ramasse-miettes (GC). Le streaming maintient un débit constant du début à la fin.

---

## 2. Les 3 pièges critiques du Streaming JPA

1. **L'illusion du streaming sans `@Transactional` :**
   * En mode par défaut (`autoCommit = true`), le pilote PostgreSQL **ignore totalement le `fetchSize`** et télécharge l'intégralité du résultat en mémoire JVM.
   * `@Transactional(readOnly = true)` est obligatoire pour activer le curseur côté base de données.
2. **Dimensionner le `fetchSize` (le sweet spot : 1 000 à 2 000) :**
   * Compromis optimal : très peu de latence réseau.
   * Au-delà de 5 000, le gain de vitesse devient marginal (< 3 %), mais immobilise inutilement de la mémoire côté PostgreSQL et JVM.
3. **Saturation silencieuse du cache L1 :**
   * Hibernate conserve chaque entité en session $\rightarrow$ risque d'`OutOfMemoryError`.
   * **Remède :** Projeter directement vers un Record / DTO pour contourner le suivi d'état d'Hibernate.

---

## 3. Quand JPA Stream reste-t-il pertinent ?

Face à `JdbcClient` qui offre un débit supérieur sans risque de cache, JPA Stream garde deux atouts majeurs :

### 1. Exploiter les méthodes calculées de l'entité

`JdbcClient` n'extrait que des colonnes brutes. JPA instancie l'objet métier complet avec ses méthodes :

```java
// Réutilisation directe de la logique métier sans recalcul en SQL
csvWriter.writeNext(new String[] {
    vin.getNom(),
    String.valueOf(vin.getPrixTTC()),  // Logique Java existante
    vin.getStatutCommercial()
});
```

### 2. Zéro plomberie SQL

Déclaration directe dans l'interface sans créer de DAO JDBC spécifique :

```java
Stream<Vin> streamAllBy();
```

---

## 4. L'alternative haute performance : Streaming JdbcClient

Pour les exports massifs bruts (CSV / JSON sans logique métier Java), `JdbcClient` offre le meilleur ratio débit / simplicité :

```java
public record VinExportDto(Integer id, String chateau, BigDecimal prix) {}

@Repository
@RequiredArgsConstructor
public class VinExportDao {
    private final JdbcClient jdbcClient;

    public void streamAll(Consumer<VinExportDto> consumer) {
        // Zéro cache L1, zéro dirty-checking, mapping direct vers le Record
        try (Stream<VinExportDto> stream = jdbcClient.sql("SELECT id, chateau, prix FROM formation.vin")
                .query(VinExportDto.class)
                .stream()) {
            stream.forEach(consumer);
        }
    }
}
```

* **Débit maximal :** Les tuples SQL sont directement désérialisés et transmis au flux de sortie.
* **Complexité maîtrisée :** Aucun cycle de vie d'entités, aucun état de session à purger.

## 5. Synthèse des bonnes pratiques d'extraction

```txt
Quel est l'objectif ?
 │
 ├── 1. Affichage écran / Navigation IHM
 │       ├── Petit volume (< 1 000) ──► ✅ JPA classique (List<T>)
 │       └── Grand volume            ──► ⚠️ Bannir OFFSET / LIMIT
 │                                       ✅ Pagination par curseur (keyset) :
 │                                          WHERE id > :dernierId LIMIT 50
 │
 └── 2. Export de données (CSV / JSON)
         ├── Volume modéré (< 20 000) ──► ✅ JPA Projection DTO synchrone
         ├── Gros volume + logique     ──► ✅ JPA Stream + StreamingResponseBody
         └── Gros volume brut (> 50k)  ──► ✅ JdbcClient Stream
```
