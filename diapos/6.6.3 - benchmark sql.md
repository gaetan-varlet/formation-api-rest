# Benchmark & Stratégies d'extraction de données

----

## 1. Matrice comparative sur gros volume (~500 000 lignes)

| Approche | Empreinte RAM | Vitesse | Complexité dev | Cas d'usage type |
| :--- | :--- | :--- | :--- | :--- |
| **JPA Entités (`List<Vin>`)** | **$O(N)$** | 🐌 Lent | ⭐ (1/5) | CRUD quotidien, listes paginées (< 1 000) |
| **JPA DTOs (`List<VinDto>`)** | **$O(N)$** (Divisé par 2) | 🚗 Moyen | ⭐⭐ (2/5) | Données en lecture seule (< 20 000) |
| **JPA Stream (`Stream<T>`)** | **$O(1)$** | ⚡ Rapide | ⭐⭐⭐⭐ (4/5) | Gros volume nécessitant la logique métier |
| **JDBC Stream (`JdbcClient`)** | **$O(1)$** (Minimal, ~15 Mo) | 🚀 Maximal | ⭐⭐ (2/5) | Exports massifs bruts (CSV / JSON) |

----

## 2. Pourquoi JPA Stream est plus exigeant qu'il n'y paraît

Écrire `Stream<Vin>` est simple, mais impose 3 contraintes d'infrastructure en production :

1. **Saturation silencieuse du cache L1 :**
   - Par défaut, Hibernate attache chaque entité lue au contexte de persistance (`EntityManager`).
   - Sur 500 000 entités, le cache grossit au fil de l'eau -> risque d'`OutOfMemoryError`.
2. **Le piège du pilote JDBC (PostgreSQL) :**
   - `fetchSize = 0` par défaut : le pilote télécharge tout en mémoire avant de renvoyer le premier élément.
   - Obligation de positionner un hint explicite (`HibernateHints.HINT_FETCH_SIZE = 2000`).
3. **Maintien de la connexion :**
   - La transaction `@Transactional` et la connexion HikariCP restent mobilisées pendant toute la durée du stream réseau.

> **Bonne pratique JPA :** Projeter immédiatement vers un DTO (`SELECT new VinDto(...)`) pour désactiver le cache L1 d'Hibernate.

----

## 3. Quand JPA Stream reste-t-il pertinent ?

Si `JdbcClient` est plus rapide, pourquoi s'embêter avec JPA Stream ?

### 1. Pour réutiliser la logique métier de l'entité

`JdbcClient` ne ramène que des colonnes SQL brutes. JPA instancie le vrai objet Java avec ses méthodes calculées :

```java
// Dans l'export CSV : réutilisation directe du code Java existant
csvWriter.writeNext(new String[] {
    vin.getNom(),
    String.valueOf(vin.getPrixTTC()),  // Méthode calculée dans Vin.java
    vin.getStatutCommercial()          // Logique métier interne
});
```

### 2. Pour la simplicité d'architecture

- **Zéro SQL manuel :** Pas besoin d'écrire et maintenir de requête `SELECT ... FROM ...`.
- **Tout reste dans le Repository :** Une seule ligne déclarée dans `VinRepository`, sans créer de classe DAO Jdbc séparée :

  ```java
  Stream<Vin> streamAllBy();
  ```

----

## 4. L'alternative radicale : le Streaming JdbcClient

Pour un export en lecture seule (CSV, JSON), contourner l'ORM simplifie le code et élimine les effets de bord de session :

```java
public record VinExportDto(Integer id, String chateau, BigDecimal prix) {}

@Repository
@RequiredArgsConstructor
public class VinExportDao {
    private final JdbcClient jdbcClient;

    public void streamAll(Consumer<VinExportDto> consumer) {
        // Zéro cache L1, zéro dirty-checking, mapping direct vers le Record
        try (Stream<VinExportDto> stream = jdbcClient.sql("SELECT id, chateau, prix FROM formation.vin")
                .query(VinExportDto.class)
                .stream()) {
            stream.forEach(consumer);
        }
    }
}
```

- **Débit maximal :** Envoi direct des tuples du curseur JDBC vers le flux réseau.
- **Complexité réduite :** Pas de cycle de vie d'entités, pas de désynchronisation de cache.

## 5. Arbre de décision : que choisir en pratique ?

```txt
Quel est le besoin d'extraction ?
 │
 ├── 1. Affichage écran / Pagination standard (< 1 000 lignes)
 │       └── ✅ JPA classique (List<Vin> / Pageable)
 │            → Simple, rapide à coder, impact RAM négligeable.
 │
 ├── 2. Extraction moyenne sans calculs (1 000 à 20 000 lignes)
 │       └── ✅ JPA avec Record / DTO (List<VinDto>)
 │            → Évite la surcharge Hibernate tout en restant synchrone.
 │
 ├── 3. Gros volume avec logique Java / calculs métier (> 20 000 lignes)
 │       └── ✅ JPA Stream (Stream<Vin> + StreamingResponseBody)
 │            → Empreinte RAM stable (O(1)), permet d'appeler vin.getPrixTTC().
 │
 └── 4. Export brut massif sans logique métier (CSV / JSON)
         └── ✅ JdbcClient Stream (.query(VinRecord.class).stream())
              → Vitesse maximale, RAM minimale, sans passer par l'ORM.
```
