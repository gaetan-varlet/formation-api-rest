Cet exercice part volontairement de **Java EE / Jakarta EE (Servlets) sans framework** (Tomcat 11, `web.xml`, `jakarta.servlet`) pour vous montrer toute la plomberie manuelle nécessaire sans framework — et mieux apprécier ce que **Spring Boot** automatisera dès le module suivant.

## Création d'une application web classique avec Maven

<Steps>

1. **Créer le projet Maven**

   Choisissez l'option *skip archetype* et le packaging `war`, ou utilisez la commande :

   ```bash
   mvn archetype:generate -DgroupId=fr.insee -DartifactId=toto -DarchetypeArtifactId=maven-archetype-quickstart -DarchetypeVersion=1.4 -DinteractiveMode=false
   ```

2. **Ajouter le descripteur de déploiement**

   Créez `src/main/webapp/WEB-INF/web.xml` (pour un déploiement sur **Tomcat 11** / Jakarta Servlet 6.1) :

   ```xml title="src/main/webapp/WEB-INF/web.xml"
   <web-app xmlns="https://jakarta.ee/xml/ns/jakartaee"
       xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance"
       xsi:schemaLocation="https://jakarta.ee/xml/ns/jakartaee
           https://jakarta.ee/xml/ns/jakartaee/web-app_6_1.xsd"
       version="6.1">
   </web-app>
   ```

3. **Configurer Java 25 et l'API Servlet dans `pom.xml`**

   ```xml title="pom.xml"
   <dependencies>
       <dependency>
           <groupId>jakarta.servlet</groupId>
           <artifactId>jakarta.servlet-api</artifactId>
           <version>6.1.0</version>
           <scope>provided</scope>
       </dependency>
   </dependencies>
   <build>
       <plugins>
           <plugin>
               <groupId>org.apache.maven.plugins</groupId>
               <artifactId>maven-compiler-plugin</artifactId>
               <version>3.16.0</version>
               <configuration>
                   <release>25</release>
               </configuration>
           </plugin>
           <plugin>
               <groupId>org.apache.maven.plugins</groupId>
               <artifactId>maven-war-plugin</artifactId>
               <version>3.5.1</version>
           </plugin>
       </plugins>
   </build>
   ```

</Steps>

:::tip[Lancer Tomcat depuis IntelliJ IDEA]
Pour démarrer et déployer facilement l'application sur Tomcat depuis IntelliJ IDEA (y compris en version Community Edition), installez le plugin **Smart Tomcat**, puis créez une configuration *Smart Tomcat* en indiquant le dossier d'installation de **Tomcat 11** et le *Context path* `/` (afin d'accéder aux endpoints directement sur `http://localhost:8080/...`).
:::

## Évolution progressive : de la JSP à l'API JSON

Parcourez les 5 étapes ci-dessous pour comprendre comment on passe historiquement d'une application **monolithique** (où le serveur génère toute la page HTML) à une **API JSON** moderne — tout en constatant la plomberie technique encore nécessaire avec les servlets brutes :

:::tip[Inspectez chaque réponse dans votre navigateur (F12 — onglet Réseau)]
À chaque étape, ouvrez les outils de développement du navigateur (`F12` → onglet *Réseau* / *Network*, puis rechargez la page et cliquez sur la requête) pour comparer :
- l'en-tête **`Content-Type`** retourné (`text/html`, `text/plain`, `application/json`) ;
- le **corps brut de la réponse** généré par le serveur et son rendu dans le navigateur.
:::

<Tabs>
  <TabItem label="1. Servlet + JSP">

**Point de départ historique (application monolithique) :** le serveur effectue le traitement Java, puis passe le relais à une page **JSP** qui génère tout le HTML envoyé au navigateur.

Créez la servlet dans `src/main/java/servlet/` et la JSP dans `/WEB-INF/jsp/` :

```java title="CalculAvecJspServlet.java"
package servlet;

@WebServlet("/calcul-avec-jsp")
public class CalculAvecJspServlet extends HttpServlet {

    public void doGet(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        int nombre1 = Integer.parseInt(request.getParameter("nombre1"));
        int nombre2 = Integer.parseInt(request.getParameter("nombre2"));
        int somme = nombre1 + nombre2;
        int produit = nombre1 * nombre2;
        request.setAttribute("somme", somme);
        request.setAttribute("produit", produit);

        response.setContentType("text/html");
        response.setCharacterEncoding("UTF-8");
        this.getServletContext().getRequestDispatcher("/WEB-INF/jsp/reponse-calcul.jsp")
            .forward(request, response);
    }
}
```

```html title="WEB-INF/jsp/reponse-calcul.jsp"
<!DOCTYPE html>
<html>
    <head>
        <meta charset="utf-8" />
        <title>Calcul avec JSP</title>
    </head>
    <body>
        <p>Calcul avec affichage de la réponse dans la JSP :</p>
        <p>La somme de ${param.nombre1} et ${param.nombre2} est égale à ${requestScope.somme}.</p>
        <p>Le produit de ${param.nombre1} et ${param.nombre2} est égal à ${requestScope.produit}.</p>
    </body>
</html>
```

Test (après déploiement à la racine de Tomcat) : [http://localhost:8080/calcul-avec-jsp?nombre1=3&nombre2=4](http://localhost:8080/calcul-avec-jsp?nombre1=3&nombre2=4)

  </TabItem>
  <TabItem label="2. Servlet HTML">

**Toujours monolithique, sans moteur de vue :** on supprime la JSP et on écrit directement le HTML dans le flux de réponse (`PrintWriter`). On constate vite à quel point mélanger du HTML dans du Java est pénible à maintenir — et ce résultat reste destiné à un humain, pas à une autre application.

```java title="CalculServlet.java"
package servlet;

@WebServlet("/calcul")
public class CalculServlet extends HttpServlet {

    public void doGet(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        int nombre1 = Integer.parseInt(request.getParameter("nombre1"));
        int nombre2 = Integer.parseInt(request.getParameter("nombre2"));
        int somme = nombre1 + nombre2;
        int produit = nombre1 * nombre2;

        response.setContentType("text/html");
        response.setCharacterEncoding("UTF-8");
        PrintWriter out = response.getWriter();
        out.println("<!DOCTYPE html>");
        out.println("<html>");
        out.println("<head>");
        out.println("<meta charset=\"utf-8\" />");
        out.println("<title>Calcul</title>");
        out.println("</head>");
        out.println("<body>");
        out.println("<p>Calcul avec affichage de la réponse dans la servlet :</p>");
        out.println("<p>La somme de " + nombre1 + " et " + nombre2 + " est égale à " + somme + ".</p>");
        out.println("<p>Le produit de " + nombre1 + " et " + nombre2 + " est égal à " + produit + ".</p>");
        out.println("</body>");
        out.println("</html>");
    }
}
```

Test : [http://localhost:8080/calcul?nombre1=3&nombre2=4](http://localhost:8080/calcul?nombre1=3&nombre2=4)

  </TabItem>
  <TabItem label="3. API text/plain">

**Première étape vers une API (données uniquement) :** le serveur ne renvoie plus de mise en forme HTML, mais uniquement le résultat brut en `text/plain`. Problème : ce format libre est compliqué à lire automatiquement et oblige chaque client à écrire un découpage de chaîne fragile — d'où le passage à un format structuré comme **XML** ou **JSON** à l'étape suivante.

```java title="CalculTextPlainServlet.java"
package servlet;

@WebServlet("/calcul-text-plain")
public class CalculTextPlainServlet extends HttpServlet {

    public void doGet(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        int nombre1 = Integer.parseInt(request.getParameter("nombre1"));
        int nombre2 = Integer.parseInt(request.getParameter("nombre2"));
        int somme = nombre1 + nombre2;
        int produit = nombre1 * nombre2;

        response.setContentType("text/plain");
        response.setCharacterEncoding("UTF-8");
        PrintWriter out = response.getWriter();
        out.println("somme:" + somme + ", produit:" + produit);
    }
}
```

Test : [http://localhost:8080/calcul-text-plain?nombre1=3&nombre2=4](http://localhost:8080/calcul-text-plain?nombre1=3&nombre2=4)

  </TabItem>
  <TabItem label="4. API JSON manuel">

**Passage à un format structuré (`application/json`) :** les données deviennent facilement exploitables par n'importe quel client, mais construire le JSON par concaténation de chaînes reste laborieux et très fragile (guillemets, échappement, listes ou objets imbriqués).

```java title="CalculJsonServlet.java"
@WebServlet("/calcul-json")
public class CalculJsonServlet extends HttpServlet {

    public void doGet(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        int nombre1 = Integer.parseInt(request.getParameter("nombre1"));
        int nombre2 = Integer.parseInt(request.getParameter("nombre2"));
        int somme = nombre1 + nombre2;
        int produit = nombre1 * nombre2;

        response.setContentType("application/json");
        response.setCharacterEncoding("UTF-8");
        PrintWriter out = response.getWriter();
        out.println("{\"somme\":" + somme + ", \"produit\":" + produit + "}");
    }
}
```

Test : [http://localhost:8080/calcul-json?nombre1=3&nombre2=4](http://localhost:8080/calcul-json?nombre1=3&nombre2=4)

  </TabItem>
  <TabItem label="5. API JSON + Jackson">

**Sérialisation automatique (véritable API JSON) :** pour éviter la concaténation manuelle, on ajoute **Jackson** dans le `pom.xml` afin de convertir directement nos objets Java en JSON :

```xml title="pom.xml"
<dependency>
    <groupId>tools.jackson.core</groupId>
    <artifactId>jackson-databind</artifactId>
    <version>3.3.0</version>
</dependency>
```

Créez la classe JavaBean `Calcul.java` dans `src/main/java/model/` (ici abrégée avec **Lombok**, ou écrivez les getters et setters manuellement) :

```java title="src/main/java/model/Calcul.java"
package model;

import lombok.Getter;
import lombok.Setter;

@Getter
@Setter
public class Calcul {

    private Integer somme;
    private Integer produit;
}
```

Jackson transforme cet objet JavaBean (ou une collection) en JSON :

```json
{"somme":15,"produit":56}
[{"somme":15,"produit":56},{"somme":15,"produit":56}]
```

```java title="CalculJacksonServlet.java"
package servlet;

import tools.jackson.databind.ObjectMapper;

@WebServlet("/calcul-jackson")
public class CalculJacksonServlet extends HttpServlet {
    public void doGet(HttpServletRequest request, HttpServletResponse response)
            throws ServletException, IOException {
        int nombre1 = Integer.parseInt(request.getParameter("nombre1"));
        int nombre2 = Integer.parseInt(request.getParameter("nombre2"));
        Calcul calcul = new Calcul();
        calcul.setSomme(nombre1 + nombre2);
        calcul.setProduit(nombre1 * nombre2);

        response.setContentType("application/json");
        response.setCharacterEncoding("UTF-8");
        PrintWriter out = response.getWriter();
        ObjectMapper objectMapper = new ObjectMapper();
        objectMapper.writeValue(out, calcul);
    }
}
```

Test : [http://localhost:8080/calcul-jackson?nombre1=3&nombre2=4](http://localhost:8080/calcul-jackson?nombre1=3&nombre2=4)

> **Bilan à l'étape 5 :** on dispose bien d'une API JSON fonctionnelle, mais le code reste **très technique et répétitif** avec `HttpServlet` : il faut encore récupérer et convertir les paramètres à la main (`Integer.parseInt(request.getParameter(...))`), configurer manuellement `Content-Type` / UTF-8, ouvrir un `PrintWriter` et piloter `ObjectMapper` dans chaque servlet.

## Présentation de la spécification JAX-RS

Pour s'affranchir de toute cette plomberie `HttpServlet` et écrire des endpoints REST de façon déclarative, Java EE / Jakarta EE propose la spécification **JAX-RS**, dédiée aux API REST :

- **JAX-RS** (*Jakarta RESTful Web Services*, anciennement Java) est la spécification standard pour exposer des API REST.
- Il faut utiliser une implémentation : **Jersey** est l'**implémentation de référence** (en version **4.0.x** pour Tomcat 11 / Jakarta EE 11) :
  - la bibliothèque Jersey ;
  - Jackson pour Jersey (conversion automatique des objets en JSON) ;
  - le framework d'injection (`jersey-hk2`).

```xml title="pom.xml"
<dependency>
    <groupId>org.glassfish.jersey.containers</groupId>
    <artifactId>jersey-container-servlet</artifactId>
    <version>4.0.3</version>
</dependency>
<dependency>
    <groupId>org.glassfish.jersey.media</groupId>
    <artifactId>jersey-media-json-jackson</artifactId>
    <version>4.0.3</version>
</dependency>
<dependency>
    <groupId>org.glassfish.jersey.inject</groupId>
    <artifactId>jersey-hk2</artifactId>
    <version>4.0.3</version>
</dependency>
```

- On déclare dans `web.xml` la servlet qui joue le rôle de contrôleur frontal :

```xml title="src/main/webapp/WEB-INF/web.xml"
<servlet>
    <servlet-name>jakarta.ws.rs.core.Application</servlet-name>
</servlet>
<servlet-mapping>
    <servlet-name>jakarta.ws.rs.core.Application</servlet-name>
    <url-pattern>/rest/*</url-pattern>
</servlet-mapping>
```

- Plus besoin d'écrire la réponse avec `PrintWriter`, le contrôleur s'en charge :
  - récupération des paramètres de requête avec `@QueryParam` ;
  - `@Produces(MediaType.APPLICATION_JSON)` transforme l'objet Java en JSON et définit le `Content-Type` ;
  - `@GET` expose la ressource en `GET`.

```java title="src/main/java/resources/CalculResource.java"
package resources;

import jakarta.ws.rs.GET;
import jakarta.ws.rs.Path;
import jakarta.ws.rs.Produces;
import jakarta.ws.rs.QueryParam;
import jakarta.ws.rs.core.MediaType;
import model.Calcul;

@Path("/calcul-jersey")
public class CalculResource {

    @Produces(MediaType.APPLICATION_JSON + ";charset=utf-8")
    @GET
    public Calcul calcul(@QueryParam("nombre1") Integer nombre1, @QueryParam("nombre2") Integer nombre2) {
        Calcul calcul = new Calcul();
        calcul.setSomme(nombre1 + nombre2);
        calcul.setProduit(nombre1 * nombre2);
        return calcul;
    }
}
```

Test : [http://localhost:8080/rest/calcul-jersey?nombre1=3&nombre2=4](http://localhost:8080/rest/calcul-jersey?nombre1=3&nombre2=4)
