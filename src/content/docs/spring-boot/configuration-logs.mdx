## Configuration de Logback

Spring Boot utilise **Logback** par défaut. Les niveaux et le format de sortie se configurent directement dans `src/main/resources/application.properties` :

```properties title="src/main/resources/application.properties"
# Niveaux de logs (ERROR, WARN, INFO, DEBUG, TRACE)
logging.level.root=INFO
logging.level.fr.insee=DEBUG
# Coloration syntaxique des logs dans la console
spring.output.ansi.enabled=ALWAYS
```

<details>
<summary>Écrire les logs dans un fichier (facultatif)</summary>

Dans la majorité des cas (conteneurs Docker/Kubernetes, `systemd`, collecteurs centralisés), **écrire uniquement dans la console suffit** : la sortie standard est automatiquement captée par la plateforme ou l'outil de centralisation des logs.

Si vous devez tout de même écrire dans un fichier avec rotation automatique :

```properties title="src/main/resources/application.properties"
# Écriture dans un fichier
logging.file.name=./logs/application.log
logging.logback.rollingpolicy.file-name-pattern=${LOG_FILE}.%d{yyyy-MM-dd}.%i.log
# Taille maximum d'un fichier de log (valeur par défaut : 10MB)
logging.logback.rollingpolicy.max-file-size=10MB
# Encodage du fichier de log
logging.charset.file=UTF-8
```

</details>

## Écrire des logs dans son code Java

On utilise la façade **SLF4J** (jamais `System.out.println` dans une application). Avec **Lombok**, l'annotation `@Slf4j` génère automatiquement l'attribut `log` à la compilation, ce qui évite la déclaration manuelle via `LoggerFactory` :

<Tabs>
<TabItem label="Avec Lombok (@Slf4j)">

```java title="TestController.java"
import lombok.extern.slf4j.Slf4j;

@Slf4j
@RestController
public class TestController {

    @GetMapping("/hello")
    public String helloWorld() {
        log.info("Passage dans le controller helloWorld");
        return "Hello World !";
    }
}
```

</TabItem>
<TabItem label="Java standard (SLF4J)">

```java title="TestController.java"
import org.slf4j.Logger;
import org.slf4j.LoggerFactory;

@RestController
public class TestController {

    private static final Logger log = LoggerFactory.getLogger(TestController.class);

    @GetMapping("/hello")
    public String helloWorld() {
        log.info("Passage dans le controller helloWorld");
        return "Hello World !";
    }
}
```

</TabItem>
</Tabs>

## Logger les requêtes SQL

Deux **alternatives indépendantes** existent pour afficher les requêtes SQL en développement. **Choisissez l'une ou l'autre** selon votre besoin (ne configurez pas les deux en même temps, sinon les requêtes seront logguées en double) :

| Approche | Mise en place | Richesse des logs |
| :--- | :--- | :--- |
| **Option 1 — Hibernate** | ⚡ **Très rapide** (2 propriétés) | Requêtes générées par Hibernate uniquement, avec des `?` à la place des valeurs |
| **Option 2 — `p6spy`** | 🔧 **Plus longue** (dépendance + driver + fichier dédié) | **Toutes** les requêtes SQL (Hibernate + JDBC), **avec les valeurs réelles des paramètres** et le temps d'exécution |

<Tabs>
<TabItem label="Option 1 : Simple (Hibernate)">

```properties title="src/main/resources/application.properties"
spring.jpa.show-sql=true
spring.jpa.properties.hibernate.format_sql=true
```

**Limites :**
- Les valeurs des paramètres `?` des requêtes préparées ne sont pas affichées directement dans la requête.
- Les requêtes SQL qui ne passent pas par Hibernate (`JdbcTemplate`, `JdbcClient`, JDBC direct…) ne sont pas logguées.

</TabItem>
<TabItem label="Option 2 : Complète (p6spy)">

**p6spy** intercepte le driver JDBC pour afficher **toutes** les requêtes SQL complètes avec leurs **valeurs de paramètres** et le temps d'exécution.

<Steps>

1. **Ajouter la dépendance dans `pom.xml`**

   ```xml title="pom.xml"
   <!-- Permet d'espionner les requêtes et transactions avec la base -->
   <dependency>
       <groupId>p6spy</groupId>
       <artifactId>p6spy</artifactId>
       <version>3.9.1</version>
   </dependency>
   ```

2. **Adapter le driver et le préfixe `jdbc:p6spy:` dans `application.properties`**

   ```properties title="src/main/resources/application.properties"
   # Driver proxy p6spy
   spring.datasource.driver-class-name=com.p6spy.engine.spy.P6SpyDriver
   # Fixe l'URL de la BDD H2 via p6spy
   spring.datasource.url=jdbc:p6spy:h2:mem:testdb
   ```

3. **Créer le fichier `spy.properties` dans `src/main/resources/`**

   ```properties title="src/main/resources/spy.properties"
   driverlist=org.h2.Driver
   appender=com.p6spy.engine.spy.appender.Slf4JLogger
   # MultiLineFormat améliore la lisibilité dans les logs
   logMessageFormat=com.p6spy.engine.spy.appender.MultiLineFormat
   # excludecategories=error,info,debug,statement,result,resultset,batch,commit,rollback,outage
   excludecategories=info,debug,result,resultset,batch
   ```

</Steps>

</TabItem>
</Tabs>

:::caution[Usage réservé au développement]
N'activez pas `p6spy` (ni `show-sql`) en production : l'interception et l'affichage de toutes les requêtes avec leurs données en clair dégradent les performances et peuvent exposer des informations sensibles dans les logs.
:::
