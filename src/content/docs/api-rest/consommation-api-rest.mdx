Au-delà des tests manuels via navigateur, Insomnia, Swagger ou `curl` (vus dans [Le protocole HTTP](/formation-api-rest/fondamentaux/protocole-http/#tester-des-requêtes-http-en-pratique)), une application consomme généralement une API REST directement par code — côté front-end (**JavaScript**) ou côté back-end (**Java**).

## En JavaScript

- **Fetch** *(standard actuel, natif dans les navigateurs et Node.js)*
- **Axios** *(bibliothèque très répandue)*
- XMLHttpRequest, jQuery *(approches historiques)*

## En Java

Plusieurs approches existent selon le contexte du projet :

1. **Avec Spring Boot (recommandé)** : **`RestClient`** (ou `WebClient` pour du réactif non-bloquant) — gère automatiquement la sérialisation/désérialisation JSON, les en-têtes et la gestion d'erreurs.
2. **En Java standard sans framework (depuis Java 11)** : `java.net.http.HttpClient` (synchrone et asynchrone, support HTTP/2).
3. **Autres bibliothèques tierces** : OkHTTP, Jersey Client.
4. **Approche historique (legacy, à éviter en neuf)** : `HttpURLConnection` avec `InputStream`, **Jackson** (JSON) et **JAXB** (XML).

:::tip[Pourquoi privilégier RestClient dans ce cours ?]
Dans une application Spring Boot, `RestClient` remplace avantageusement `HttpClient` et les appels manuels à `ObjectMapper` : le code est beaucoup plus concis, lisible et s'intègre directement avec l'injection de dépendances Spring.
:::

:::caution
`RestTemplate` est déprécié depuis Spring Boot 4 / Spring 7.0 : privilégiez `RestClient`.
:::

:::note[Négociation de format (`Accept`)]
L'API de démonstration `mocktarget.apigee.net` expose deux chemins distincts (`/json` et `/xml`), ce qui permet de disposer d'un exemple public simple et sans namespace XML (`@XmlSchema` inutile). **Dans une API REST conforme à la norme HTTP, on conserve toutefois une URL unique et on précise le format attendu via l'en-tête HTTP `Accept`** (`Accept: application/json` ou `Accept: application/xml`).
:::

Création d'un projet Maven en **Java 25** avec **Jackson** *(package `tools.jackson.databind`)* et **JAXB** si vous consommez aussi du XML :

```xml title="pom.xml"
<dependency>
    <groupId>tools.jackson.core</groupId>
    <artifactId>jackson-databind</artifactId>
    <version>3.3.0</version>
</dependency>
<!-- Uniquement si vous devez aussi désérialiser du XML avec JAXB -->
<dependency>
    <groupId>org.glassfish.jaxb</groupId>
    <artifactId>jaxb-runtime</artifactId>
    <version>4.0.9</version>
</dependency>
```

Création du Bean **Person** *(l'annotation `@XmlRootElement(name = "root")` associe la classe à la balise racine `<root>` en XML — inutile pour du JSON seul avec Jackson)* :

```java title="Person.java"
import jakarta.xml.bind.annotation.XmlRootElement;

@XmlRootElement(name = "root")
public class Person {

    private String firstName;
    private String lastName;
    private String city;
    private String state;

    // getters, setters et méthode toString()
}
```

:::note[API utilisée pour les exemples `POST`]
`mocktarget.apigee.net` est pratique en `GET`, mais ne simule pas une création de ressource en `POST` (`/echo` renvoie une enveloppe technique et `/json` retourne toujours John Doe). Les exemples `POST` s'appuient donc sur **`https://jsonplaceholder.typicode.com/users`**, qui accepte notre objet `Person` en JSON et répond `201 Created` avec l'objet envoyé enrichi d'un `"id"` : on peut ainsi le désérialiser directement dans le même objet `Person`.
:::

### Avec Spring Boot : RestClient (recommandé)

`RestClient` propose une API fluide et convertit automatiquement les objets Java en JSON (et inversement) via Jackson, sans avoir à manipuler `ObjectMapper` ou `InputStream` à la main.

#### Configuration du client HTTP

Spring Boot fournit automatiquement un bean **`RestClient.Builder`** (pré-configuré avec Jackson, les timeouts…), mais **pas** directement de bean `RestClient` prêt à l'emploi.

<Steps>

1. **Déclarer un `@Bean RestClient` partagé *(optionnel, utile pour un proxy ou une config commune)***

   Déclarez une classe `@Configuration` lorsque vous voulez centraliser une configuration (proxy, `baseUrl`, en-têtes par défaut) et l'injecter telle quelle dans vos services :

   ```java title="RestClientConfig.java"
   @Configuration
   public class RestClientConfig {

       @Bean
       public RestClient personRestClient(RestClient.Builder builder) {
           SimpleClientHttpRequestFactory factory = new SimpleClientHttpRequestFactory();
           factory.setProxy(new Proxy(Proxy.Type.HTTP, new InetSocketAddress("proxy-rie.http.insee.fr", 8080)));

           return builder
               .baseUrl("https://mocktarget.apigee.net")
               .requestFactory(factory) // facultatif si pas de proxy
               .build();
       }
   }
   ```

2. **Injecter le `RestClient` dans le service**

   ```java title="PersonApiClient.java"
   @Service
   @RequiredArgsConstructor
   public class PersonApiClient {

       private final RestClient personRestClient;

       public Person getPerson() {
           return personRestClient.get()
               .uri("/json")
               .retrieve()
               .body(Person.class);
       }
   }
   ```

</Steps>

:::tip[Alternative sans étape 1 (sans configuration partagée)]
Si vous n'avez pas besoin de partager une configuration personnalisée (comme un proxy), injectez directement `RestClient.Builder` dans le constructeur de votre service :

```java title="PersonApiClient.java"
@Service
public class PersonApiClient {

    private final RestClient restClient;

    public PersonApiClient(RestClient.Builder builder) {
        this.restClient = builder
            .baseUrl("https://mocktarget.apigee.net")
            .build();
    }

    public Person getPerson() {
        return restClient.get()
            .uri("/json")
            .retrieve()
            .body(Person.class);
    }
}
```

*(Ici, on écrit le constructeur à la main plutôt que d'utiliser `@RequiredArgsConstructor`, car Spring injecte `RestClient.Builder` alors que l'attribut conservé est `RestClient` : comme le `@Service` est un singleton, le `RestClient` est ainsi construit une seule fois au démarrage au lieu d'être reconstruit à chaque appel.)*
:::

:::note[Plusieurs `RestClient` (ex. avec et sans proxy) : comment Spring choisit ?]
- **Un seul `@Bean RestClient` :** Spring injecte par type — le nom de l'attribut (`restClient`, `personRestClient`…) n'a pas d'importance.
- **Plusieurs `@Bean RestClient`** (par exemple `externalRestClient` avec proxy et `internalRestClient` sans proxy) : chaque bean porte par défaut **le nom de sa méthode `@Bean`** (ou celui passé à `@Bean("...")`). Pour lever l'ambiguïté :
  - **Avec `@RequiredArgsConstructor` (le plus simple) :** donnez à l'attribut `private final` **le même nom que la méthode `@Bean`** (`private final RestClient externalRestClient;`).
  - **Ou avec `@Primary` / `@Qualifier` :** annotez le bean principal avec `@Primary`, ou écrivez le constructeur à la main en plaçant `@Qualifier("externalRestClient")` sur son paramètre.
:::

#### Gestion des erreurs et exceptions

Contrairement à `HttpClient` du JDK (`IOException`, `InterruptedException`), **`RestClient` ne lève aucune exception vérifiée** (*checked*) : toutes ses exceptions héritent de `RestClientException` (`RuntimeException`).

On distingue **trois situations** lors d'un appel :

| Situation | Comportement de `RestClient` | Comment la traiter |
| :--- | :--- | :--- |
| **1. Code retour OK (`2xx`)** | Désérialise la réponse | `.retrieve().body(Person.class)` *(ou `.toEntity(Person.class)` pour lire aussi le statut et les en-têtes)* |
| **2. Retour HTTP en erreur (`4xx` / `5xx`)** | Lève `HttpClientErrorException` (`4xx`) ou `HttpServerErrorException` (`5xx`) | `.onStatus(...)` sur `.retrieve()`, ou `catch (RestClientResponseException ex)` |
| **3. Pas de retour** *(timeout, coupure réseau, DNS, serveur injoignable)* | Lève `ResourceAccessException` *(aucune réponse HTTP reçue)* | `try / catch (ResourceAccessException ex)` *(non capturé par `.onStatus(...)`)* |

Exemple complet combinant un traitement différencié des trois cas :

```java
try {
    // 1. Code retour OK (2xx) : désérialisation directe en Person
    return restClient.get()
        .uri("/users/{id}", id)
        .retrieve()
        // 2. Retour en erreur (4xx / 5xx) : du plus précis au plus général
        .onStatus(status -> status.value() == 404, (request, response) -> {
            throw new PersonNotFoundException(id);
        })
        // Couvre tous les autres codes 4xx et 5xx (400..599 hors 404)
        // Alternatives pour séparer les deux cas : HttpStatusCode::is4xxClientError et HttpStatusCode::is5xxServerError
        .onStatus(HttpStatusCode::isError, (request, response) -> {
            String body = new String(response.getBody().readAllBytes(), StandardCharsets.UTF_8);
            log.error("Erreur API externe [statut={}, corps={}]", response.getStatusCode(), body);
            throw new ExternalApiException("Erreur API externe : HTTP " + response.getStatusCode());
        })
        .body(Person.class);
} catch (ResourceAccessException ex) {
    // 3. Pas de retour : serveur injoignable, timeout ou erreur I/O
    throw new ServiceUnavailableException("Service externe temporairement indisponible", ex);
}
```

:::note[Sans `.onStatus(...)` et sans `@RestControllerAdvice`, que se passe-t-il ?]
- **Sans `.onStatus(...)` :** toute réponse `4xx` ou `5xx` lève par défaut une sous-classe de **`RestClientResponseException`** (`HttpClientErrorException` ou `HttpServerErrorException`), qui permet aussi de lire `ex.getStatusCode()` et `ex.getResponseBodyAsString()` dans un `catch`.
- **Si l'exception remonte hors du contrôleur sans `@RestControllerAdvice` :**
  - Si vous avez annoté votre exception avec **`@ResponseStatus(...)`** (voir [Gestion des erreurs](/formation-api-rest/api-rest/gestion-erreurs/)), Spring renvoie le code HTTP correspondant.
  - À défaut (pour une `RestClientException` brute ou une `RuntimeException` sans `@ResponseStatus`), le gestionnaire d'erreur par défaut de Spring Boot (`/error`) prend le relais, logue la *stacktrace* et renvoie **`500 Internal Server Error`** au client de votre API — même si l'API externe avait répondu `404` ou `400`.
:::

### En Java standard (sans framework) : HttpClient

#### Requêtes synchrones (GET et POST)

<Tabs>
  <TabItem label="GET synchrone">
```java
public static void requeteGetSynchroneXmlJson(String path) throws Exception {
    // requête en GET vers /xml ou /json que l'on récupère dans un String
    HttpClient httpClient = HttpClient.newBuilder()
        .proxy(ProxySelector.of(new InetSocketAddress("proxy-rie.http.insee.fr", 8080)))
        .build();
    HttpRequest httpRequest = HttpRequest.newBuilder()
        .uri(URI.create("https://mocktarget.apigee.net" + path)).GET().build();
    HttpResponse<String> response = httpClient.send(httpRequest, BodyHandlers.ofString());
    System.out.println(response.statusCode()); // 200
    System.out.println(response.headers().allValues("content-type")); // [application/xml; charset=utf-8] ou [application/json; charset=utf-8]
    System.out.println(response.body()); // le Person en XML ou JSON

    // même chose avec récupération du body dans un InputStream
    HttpResponse<InputStream> responseStream = httpClient.send(httpRequest, BodyHandlers.ofInputStream());
    String contentType = responseStream.headers().firstValue("Content-Type").orElse("");
    if (contentType.contains("application/xml")) {
        JAXBContext jc = JAXBContext.newInstance(Person.class);
        Person person = (Person) jc.createUnmarshaller().unmarshal(responseStream.body());
        System.out.println(person); // Person [firstName=John, lastName=Doe, city=San Jose, state=CA]
    } else if (contentType.contains("application/json")) {
        ObjectMapper mapper = new ObjectMapper();
        Person person = mapper.readValue(responseStream.body(), Person.class);
        System.out.println(person); // Person [firstName=John, lastName=Doe, city=San Jose, state=CA]
    } else {
        throw new IllegalStateException("On veut du XML ou du JSON !");
    }
}
```
  </TabItem>

#### Requêtes asynchrones (`sendAsync`)

<Tabs>
  <TabItem label="GET asynchrone">
```java
HttpClient httpClient = HttpClient.newBuilder()
    .proxy(ProxySelector.of(new InetSocketAddress("proxy-rie.http.insee.fr", 8080)))
    .build();
HttpRequest httpRequest = HttpRequest.newBuilder().header("Accept", "application/json")
    .uri(URI.create("https://mocktarget.apigee.net/json")).GET().build();

System.out.println(LocalDateTime.now()); // t0 : avant l'envoi
// Non bloquant : sendAsync lance la requête en arrière-plan et rend la main immédiatement
CompletableFuture<HttpResponse<String>> cfResponse = httpClient.sendAsync(httpRequest, BodyHandlers.ofString());
System.out.println(LocalDateTime.now()); // t1 ≈ t0 (quelques ms) : le thread n'est pas bloqué

// ... on peut exécuter d'autres traitements ici pendant que la requête s'exécute ...

// Bloquant : on attend explicitement que la réponse soit disponible
HttpResponse<String> response = cfResponse.join();
System.out.println(LocalDateTime.now()); // t2 : inclut la durée de l'appel réseau
System.out.println(response.statusCode()); // 200
System.out.println(response.headers().allValues("content-type"));
System.out.println(response.body());
```

**Différence avec `send(...)` (synchrone)** : `send(...)` bloque le thread dès l'appel jusqu'à réception de la réponse. Avec `sendAsync(...)`, l'envoi est **non bloquant** (le `CompletableFuture` est retourné tout de suite) et le programme ne bloque qu'au moment de `.join()`.

  </TabItem>
  <TabItem label="Multiples requêtes en parallèle">
```java
HttpClient httpClient = HttpClient.newBuilder()
    .proxy(ProxySelector.of(new InetSocketAddress("proxy-rie.http.insee.fr", 8080)))
    .build();
List<String> urls = List.of(
    "https://mocktarget.apigee.net/user?user=Alice",
    "https://mocktarget.apigee.net/user?user=Bob",
    "https://mocktarget.apigee.net/user?user=Charlie",
    "https://mocktarget.apigee.net/user?user=David",
    "https://mocktarget.apigee.net/user?user=Eve");

System.out.println(LocalDateTime.now()); // t0 : avant lancement
// Non bloquant : les 5 requêtes partent en parallèle quasi instantanément
List<CompletableFuture<HttpResponse<String>>> cfResponses = urls.stream()
    .map(url -> httpClient.sendAsync(
        HttpRequest.newBuilder().uri(URI.create(url)).GET().build(),
        BodyHandlers.ofString())
    ).toList();
System.out.println(LocalDateTime.now()); // t1 ≈ t0

// Bloquant : on attend que TOUTES les requêtes soient terminées
CompletableFuture<Void> combinedCF = CompletableFuture.allOf(cfResponses.toArray(new CompletableFuture[0]));
combinedCF.join();
System.out.println(LocalDateTime.now()); // t2 : temps ≈ durée de la requête la plus lente

// Toutes les réponses sont déjà arrivées : join() retourne immédiatement
for (CompletableFuture<HttpResponse<String>> completableFuture : cfResponses) {
    System.out.println(completableFuture.join().body());
}
System.out.println(LocalDateTime.now()); // t3 ≈ t2
```

**Gain par rapport à `N` appels synchrones** : si chaque appel réseau prend ~200 ms, 5 appels **synchrones** s'enchaînent les uns après les autres et prennent environ **5 × 200 ms = 1 000 ms** *(somme des durées)*. En **asynchrone**, les 5 requêtes s'exécutent en parallèle : le temps total correspond environ à **la requête la plus lente (~200 ms)** au lieu de la somme.

  </TabItem>
</Tabs>

### Approche historique : HttpURLConnection

:::note[Code legacy]
`HttpURLConnection` est l'API historique de Java (antérieure à Java 11). **Elle n'est plus recommandée pour de nouveaux développements** : préférez `HttpClient` en Java standard ou `RestClient` dans un projet Spring. Ces exemples sont conservés à titre informatif pour faciliter la lecture d'applications existantes.

#### Requête HTTP en GET

```java
System.setProperty("http.proxyHost", "proxy-rie.http.insee.fr");
System.setProperty("http.proxyPort", "8080");

// requête en GET avec réponse en XML
URL url = URI.create("https://mocktarget.apigee.net/xml").toURL();
HttpURLConnection connection = (HttpURLConnection) url.openConnection();

// requête en GET avec réponse en JSON

connection.setRequestMethod("GET");

Person person = mapper.readValue(response, Person.class);
```
